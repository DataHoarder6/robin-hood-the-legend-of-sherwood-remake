## v0.1.0

Tag summary: Robin Hood: The Legend of Sherwood — Rust port 0.1.0

### What's new

- **Sherwood perk purchases.** A sixth Sherwood HUD button opens a perks panel
  with one row per campaign character and perk; Return/Space or a click on an
  affordable row buys it through the host-authority
  `PlayerCommand::CampaignPurchasePerk`. Perks cost clovers from
  `CampaignValue::Amulets`, and a purchase is refused when it would spend the
  last one, because that clover is the VIP death save
  (`MINIMUM_CLOVERS_AFTER_PURCHASE`). One rule, `perk_purchase_state`, produces
  both the panel's row state and the authoritative answer, so a row the panel
  offers is exactly a row the engine accepts. Four perks exist: fight through a
  swordfight, loot a knock-out, and no friendly-fire damage or knockback. The
  button reuses the clover icon and the "Amulets" unit string because no perk
  art or perk-specific cost word exists.
- **Multiplayer desync recovery.** A client hash mismatch requests diagnostics,
  suspends gameplay and reconnects for a fresh host snapshot. Input resumes only
  after the readiness barrier; pending recovery suppresses duplicate requests.
  Complete live command batches and late-input journals use stable player-seat
  ordering, preventing packet batch boundaries from changing command execution.
- **Fresh-mission parity capture.** A reproducible capture controller inventories
  playable missions, starts ten independent 60-second random-input runs for each,
  and admits only complete fresh-start traces. See `docs/TESTING.md`.

## v0.2.0

Tag summary: v0.2.0: multiplayer and campaign co-op, bounded waits, crash reporting

### What's new

- **Campaign map mission availability.** Every map pin now carries the
  campaign's own answer for its mission: a filled gold corner marks a mission
  that can start now, a hollow pale-blue corner marks a completed mission that
  can be replayed, and a dimmed pin with a dark corner marks a locked one. The
  state comes once from `accessible_mission_indices` plus the attempt record
  (`Campaign::is_mission_accessible` / `is_mission_replayable`), so no pin can
  offer a commit the engine would reject. Clicking or pressing Return on a
  locked pin starts nothing; the tooltip and the description window name the
  unmet condition instead of offering the start action. The map opens on the
  first ready pin.
- **Campaign co-op is one session.** A campaign host advertises a joinable
  lobby — `campaign` plus the fixed party size and no explicit roster — so a
  second seat joins from its own install and needs no local save. The host owns
  the campaign: its slot, its roster and its mission sequence. The session spans
  the campaign's missions, so the mission-end page hands every seat to the next
  mission instead of ending the session and leaving each install to write its
  own save; a joining seat never writes a campaign slot. A campaign host with a
  save resumes at the mission the party is on, a fresh one at the mission its
  lobby advertised. `--mp-campaign` starts the same session from the command
  line, and a lobby whose rules cannot be advertised names the reason in its
  status line instead of sitting there as if it were open.

## v0.3.0

Tag summary: Robin Hood 0.3.0 — D06 fixed, full H23 release gate observed

### What's new

- **Opt-in teammate cursors.** In co-op, a profile preference under Options →
  Multiplayer / Privacy ("Show Teammate Cursors") shows other seats' cursors in
  real time, smaller and tinted in that seat's colour, and broadcasts your own
  cursor while enabled. It is off by default. Cursor state travels as a
  presentation-only, host-relayed message on the existing reliable stream
  (world coordinates, never screen pixels), is buffered 120 ms and interpolated
  for smoothness, and disappears for stale or disconnected peers. It never
  enters simulation, snapshots, replays, or state hashes. Browser builds use
  the same wire path but have no privacy-screen entry point yet.
- **Empty selection boxes leave your party alone.** A left-drag box that
  catches no selectable hero and no controllable allied soldier dispatches no
  selection command: heroes, allied soldiers, the selected action, and
  portraits stay as they were. Soldiers count only while
  `control_tactical_units` is on. A box with any hit still replaces both
  selections unless Shift is held; clicking units, clicking ground, and
  right-dragging keep their existing behaviour. This is a post-port convenience,
  not original-game behaviour; the decision is recorded in
  `docs/adr/0001-empty-box-selection-is-not-a-deselect.md`.
